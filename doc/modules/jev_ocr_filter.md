# Jev OCR filter (experimental)

The optional `LLMTranslator` **Jev 處理異常字元 (Experimental)** setting defaults to false. When enabled, only the first full-page Codex translation timeout invokes Jev, after the timed-out request has closed. Normal OCR and successful translations do not call Jev. The translator then retries once with the same model and immutable context; no OCR rescan occurs. Partial selections without full-page coverage, non-Codex requests and disabled rescue retain ordinary retries.

Enter the official key under **LLM Profiles → TypeSafe API Key (Jev)**; it saves as `module.ocr_jev_typesafe_api_key`. **OpenRouter reuses the API key from the existing OpenRouter LLM profile** (stable ID `openrouter`, even if renamed); no separate Jev OpenRouter key is required. Both use the normal LLM secret storage and `config/config.json` save/load workflow. Each provider's nonempty saved key takes precedence over its environment variable (`TYPESAFE_API_KEY` or `OPENROUTER_API_KEY`); an empty or missing profile key uses that variable. Other profiles' keys are never selected implicitly. Set environment variables before starting the app. The integration uses the existing `requests` dependency.

The Run dialog's Translation section contains the **Jev API provider** dropdown, which saves `module.ocr_jev_provider`: `typesafe` (official, default) or `openrouter`. Missing or invalid saved selections default to TypeSafe. Selection is independent of available keys; `JEV_API_PROVIDER` is not used. Keys never cross providers, and missing keys or request failures do not trigger provider fallback. TypeSafe uses `https://api.typesafe.ai/v1/systemone` with `jev-latest`; OpenRouter uses `https://openrouter.ai/api/v1/systemone` with `~typesafe/jev-latest`. Both use the same typed decisions and screening policy. See the [OpenRouter Jev guide](https://openrouter.ai/docs/guides/community/jev).

`modules/ocr/jev_filter.py` owns screening; `LLMTranslator._translate` invokes it once on the timed-out page's nonempty translation sources. Its initial screen finds suspicious pieces, including short strings, symbols and mixed scripts. No source images or translations are sent. One cleanup invocation can make several HTTP requests; it is not a one-request limit.

Cleaned sources are private to that retry. Original OCR, block identities and geometry remain unchanged. Empty cleaned sources retain their request IDs and yield empty translations; the response cannot repopulate them. Only a valid retranslation publishes translations. A second timeout or invalid response ends the page attempt without another cleanup or retry. Cancellation and account errors still propagate; missing keys or invalid Jev decisions retain affected text and the single retranslation uses that retained text. The old `ocr_jev_filter` switch and OCR-rescan model setting are discarded by existing permissive config loading.

Scope is recognition debris: mechanical repetition and unintelligible broken strings, including garbled Latin/English. Dialogue, narration, titles, explanations, names, statistics, meaningful notation, deliberate cries and readable language with ordinary OCR mistakes must be preserved. Normal credits, copyright, URLs and release announcements are also content, not noise. Translation quality, grammar, narrative coherence and factual correctness are outside the decision. Text-only uncertainty favors preservation; neither fluent hallucinations nor unfamiliar names can be verified against images by this service.

## Semantic cleanup

The initial screen asks Jev separate Noul questions about recognition breakdown, usable content, intentional expression and whole-span deletion safety. Batches contain at most four source pieces of 512 characters, with adjacent original context for split blocks. A short or unfamiliar string is never discarded by a character-pattern rule.

An initial judgment favoring intentional expression over recognition breakdown protects the source block from ordinary deletion, even across split pieces. Long letter-only repetitions have a separate shortening path: Jev must favor removing redundant copies and classify the repeated unit as a nonlexical sound, with both choices' confidence and selected probability at least 0.85. The edit retains eight copies and every surrounding character; it cannot clear the cry, shorten numbers or rewrite names. Candidate patterns alone never authorize an edit. The same expression protection stops ordinary cleanup passes once an intentional expression remains.

A separate Jev question checks established written reactions and Internet laughter conventions before a suspicious piece is cleaned. Plausible conventions such as Japanese `www` or Korean `ㅋㅋ` are retained. Keeping this narrow decision separate avoids broadly redefining all repeated or pronounceable debris as laughter.

For a potentially damaged piece, exact repetition boundaries supplement a uniform source-position grid with Jev-refined boundaries. This helps isolate loops beside punctuation or statistics without hiding nonrepeating debris elsewhere. These are location proposals, not permission to delete. Exact source slices are verified for usable content, intentional expression, symbolic/structural function, meaning loss and cuts through recognizable words. Long removals also receive overlapping short-window checks, because a long loop can hide useful text at its edges or in its middle. Whole-span deletion has its own policy and cannot bypass this protection through the partial-edit path.

When several candidates pass, the filter prefers Jev's evidence for a faithful edit, not the longest deletion. A final check examines both boundary characters between the retained prefix and suffix: a long removed run can hide a legitimate delimiter's function. A positive notation judgment vetoes the selected edit without falling back to a less faithful candidate. The filter makes at most three cleanup passes per source piece. Only original characters are removed; no generated replacements, spelling corrections or reconstructed words are accepted. Uncertain boundaries can leave residual noise.

Choice requests use bounded tournaments over the same source candidates. Each comparison stays within 255 options and a conservative 16,000-byte budget for its UTF-8 JSON representation before ASCII escaping; option count alone does not prevent API token-limit errors. This budget is an implementation safeguard, not a claim about the provider's exact token or wire-size limit. Identical valid requests share a cache only within the current filter call.

The thresholds in `_JevFilter` are calibrated policies, not accuracy guarantees. Changing them requires real-model evaluation of whole noise, partial noise, normal controls, and preservation of usable text **inside** damaged blocks. A clean standalone-control score alone is insufficient. Jev's confidence and probabilities are not independent proofs of correctness; see [confidence](https://docs.typesafe.ai/confidence) and [atomic decisions](https://docs.typesafe.ai/concepts/how-to-build-with-system-one).

## Failure and persistence contract

Only OCR text changes; images and translations are not edited. Existing **Remove empty textblocks** behavior controls whether cleared blocks are removed in the page pipeline. Original and retained text are logged; this is an audit record, not project-level undo.

Jev statistics report actual HTTP request attempts and provider-reported **input tokens only**. `requests` excludes cache hits and skipped calls; sent requests still count after network/HTTP errors, invalid decisions or cancellation. Missing input reports are listed as `missing_input_usage_requests`, not assumed to consume zero; `input_tokens` is the sum of available reports. Output and total tokens are not accumulated. `LLMTranslator.jev_cleanup_totals` holds these counters alongside cleanup counts and cost; each parallel page collects its own counters before merging under the translator's context lock; the run manager resets and reports them independently of the OCR/translation full-token and cost totals.

Request logs, JSON audits and cleanup summaries report USD cost. A valid `usage.cost`, including zero, takes precedence; otherwise reported input tokens estimate cost at **$0.042 per million**, with free output ([TypeSafe](https://typesafe.ai/), [OpenRouter](https://openrouter.ai/typesafe/jev-1.13), rates checked 2026-09-25). `cost_source` distinguishes `reported`, `estimated`, `mixed` or `none`; an estimate is not an account bill. If any sent request cannot be priced, `cost_usd=unavailable`, `priced_subtotal_usd` contains only known amounts and `unpriced_requests` counts the gaps. No sent requests means zero cost. Integer nanodollar counters preserve additive merging and JSON serialization; formatted amounts use nine decimal places. Raw provider usage remains in request audits. No extra API calls are made to price requests.

Each filter call emits a concise `Jev OCR cleanup` summary; `Jev OCR cleanup run` totals are reset and reported alongside run token usage. `changed_blocks` counts each changed output block once, split into `cleared` (whole text cleared) and `trimmed` (partial deletion or repeat shortening). `removed_characters` counts source characters, not tokens; `kept_blocks` includes uncertain, skipped and failed blocks and does not certify correct OCR. `changed_calls` is changed filter calls / all filter calls (timed-out pages). Cache hits and repeated decisions never add removals; rolled-back edits count as kept. These are filter outputs, not proof of later project persistence.

Structured `Jev OCR filter audit:` JSON records use the existing application log and its retention policy. An `audit_id` groups one filter call; `source` identifies the project image when invoked from the translation pipeline. Direct calls may supply `source`, otherwise it is null. Block numbers are one-based translation-input IDs; already-empty OCR blocks were excluded by the translator; scoped character offsets are zero-based, end-exclusive. `request` records contain the exact text, questions/candidates, raw answers and probabilities, usage, HTTP status, elapsed time and error type. `cache_hit` refers to an earlier request hash without charging it again. API keys and authorization headers are not included. These records are for inspection, not additional translation-model input.

`finished` records with status `completed` describe returned filter output. Each block includes original/retained text, removed-character count, action (`kept`, `cleared`, `trimmed`) and a control-flow reason. `no_approved_edit` does not certify correct OCR. A schema-valid request likewise does not authorize deletion by itself. Cancellation or an escaping error reports the original text as retained, even if earlier decisions approved candidate edits. Status `skipped` distinguishes empty input, missing keys and invalid providers; these make no requests and preserve the input. Later OCR postprocessing or project saving is outside this filter record. Questions and scores are the decision evidence; no model rationale is invented.

Missing credentials retain all text. Network errors, unsupported/invalid decisions or missing probabilities retain the entire affected source block, including deletions approved in earlier passes or pieces. Other blocks can continue. There are no filter retries; connect/read timeouts are 5/20 seconds. Cancellation is checked before requests, cache reads and after responses; it cannot interrupt an outstanding synchronous HTTP read.

Verify with `python -m pytest tests/test_jev_ocr_filter.py tests/test_llm_run_usage.py tests/test_llm_ocr.py tests/test_run_pipeline_dialog.py -q`. Mocked tests protect source preservation, bounded requests, usage accounting, cancellation, rollback and provider isolation; real-model efficacy must be measured separately without embedding sample-specific exceptions in production.
