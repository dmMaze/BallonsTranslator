# 添加翻译器

本地扩展放在 `custom_modules/trans_<name>.py`；内置模块放在
`ballontranslator/modules/translators/trans_<name>.py`。添加文件后重启应用。
模块发现只读取静态元数据，不导入具体实现；不要在 `__init__.py` 中增加提前导入。

## 最小示例

使用英文主指南中的[完整示例](how_to_add_new_translator.md#minimal-module)，
保存为 `custom_modules/trans_example.py`。示例只复制原文，无需 API 或模型，
可用来验证注册、语言选择和结果映射。可运行代码只在主指南维护。

## 扩展约定

- 继承 `BaseTranslator`，用 `register_translator` 注册唯一且稳定的名称；
  该名称会写入配置。语言名称使用 `base.py` 中的 `LANGMAP_GLOBAL` 键，
  `lang_map` 的值填写服务使用的语言代码。
- `_translate` 接收字符串列表，返回数量和顺序一致的字符串列表。
  支持列表的 API 和本地模型使用 `concate_text=False`；只有服务能保留
  分隔符时才使用合并模式。公共 `translate()` 处理单个字符串、空输入和模型加载。
- 参数放在类级 `params` 中，通过 `get_param_value()` 读取；只在需要更新
  运行时状态时重写 `updateParam()`，并先调用基类实现。
- 参数和语言信息必须能由惰性注册器静态读取。非对称语言支持可使用返回
  固定列表的 `supported_src_list` / `supported_tgt_list` 属性。
  设置界面不能依赖构造、初始化、下载、模型加载或网络调用获取元数据。
- 重型模型使用 `BaseModule` 的 `_load_model_keys` / `_load_model` 生命周期，
  保留工作线程和无界面模式。共享 LLM 上下文的归属见 [LLM 指南](modules/llm_translator.md)。

## 验证

使用主指南的[验证命令](how_to_add_new_translator.md#verification)。真实翻译器还需
验证初始化前的元数据、字符串/列表/空输入、结果数量与顺序、服务和模型失败路径；
自动化测试应模拟网络服务。遵守 [AGENTS.md](../AGENTS.md#verification)，
确认打开设置不会加载模型或访问服务。
